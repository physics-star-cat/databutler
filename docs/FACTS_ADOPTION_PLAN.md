# Verified Facts v0.2 — adoption plan

Written 2026-10-12 alongside `docs/FACTS_PROTOCOL.md`. The question this plan answers is not "how do we build it" (that is `docs/superpowers/plans/2026-10-12-facts-protocol-v02.md`) but "once built, what gets it **found and used** by Claude, ChatGPT, Copilot, Perplexity and the agent frameworks?" Every action is ranked by expected discovery per hour of work, with the effort and whether the owner must do it by hand.

Baseline to beat (webmon, 2026-10): a handful of real agent calls a day across the estate; most focused servers see one registry health probe a day; the `changes` endpoint's ~88 calls a week is the strongest real-usage signal Data Butler has; Copilot/Bing AI citations run to tens of thousands a month across the family sites while search clicks are in the hundreds.

## 1. What we found (October 2026)

Short, with links; anything not checked against a primary source is marked UNVERIFIED.

**Where agents and their users discover tools today**

- **Official MCP Registry** (registry.modelcontextprotocol.io, `server.json`): in preview since 2025-09-08, API frozen at v0.1, GA/v1 not confirmed as of this month ([registry repo](https://github.com/modelcontextprotocol/registry); status via [secondary guides](https://atlan.com/know/ai-agent/what-is-an-mcp-registry.md), UNVERIFIED GA date). It is the upstream feed: PulseMCP ingests it; GitHub's MCP Registry (Sept 2025) and Copilot surface it to developers ([overview](https://tallyfy.com/how-to-list-mcp-server-registry-smithery-glama-pulsemcp/), secondary). Data Butler already publishes `io.github.physics-star-cat/databutler-*` there.
- **Directories that crawl**: Smithery (~3–7k listings), Glama (~20–37k servers mid-2026, quality scoring, owner-claimed tier), PulseMCP (curated). Numbers conflict across vendor blogs ([TrueFoundry](https://www.truefoundry.com/blog/best-mcp-registries), UNVERIFIED). Claiming a listing matters more than the listing.
- **Claude Connectors Directory**: open to any organisation; remote MCP servers accepted; requirements are tool `title` + `readOnlyHint`/`destructiveHint` on every tool (missing annotations cause ~30% of rejections), OAuth only if the service needs sign-in, documentation, and a privacy policy ([submission docs](https://claude.com/docs/connectors/building/submission), [FAQ](https://support.claude.com/en/articles/11596036-anthropic-mcp-directory-faq)). Data Butler already meets the annotation and privacy requirements.
- **ChatGPT app directory (Apps SDK)**: submissions open via the Platform Dashboard; the SDK is MCP-based and still labelled preview; organisation verification is a hard gate; public Terms, Privacy Policy and a support contact are required; review covers security, capability and UX; "an app that just relays another service" is a cited rejection reason ([alpic guide](https://alpic.ai/blog/how-to-submit-your-app-to-the-chatgpt-directory), [tallyfy guide](https://tallyfy.com/how-to-submit-mcp-app-openai-chatgpt/) — both secondary, UNVERIFIED against OpenAI's docs).
- **Perplexity**: custom remote MCP connectors exist for paid tiers (Pro/Max/Enterprise), added by URL; no public connector directory found; the CTO said in March 2026 the company stopped using MCP *internally* because of tool-definition context cost and per-server auth friction ([noqta.tn](https://www.noqta.tn/en/news/perplexity-drops-mcp-api-cli-agent-architecture-2026), [designrevision](https://designrevision.com/blog/perplexity-mcp); secondary, UNVERIFIED). Lesson: plain HTTPS GET with no auth is the Perplexity-compatible surface, and a 3-tool server is the MCP-compatible one.
- **Microsoft NLWeb / Copilot**: launched at Build 2025 as an open project (every NLWeb instance is an MCP server; built on schema.org + RSS). 2026 status, Cloudflare AutoRAG support and any Copilot integration rest on a single self-published post — UNVERIFIED ([launch coverage](https://www.businesstoday.in/amp/technology/news/story/microsoft-unveils-nlweb-project-to-turn-every-website-into-an-ai-enabled-app-477078-2025-05-21)). Not a channel to build for yet.
- **llms.txt**: 36k sites by May 2026, but Ahrefs' 137k-domain log study found 97% of llms.txt files got zero requests and AI retrieval bots were 1.1% of what traffic there was; GPTBot 4.5%, ClaudeBot 0.8% ([ppc.land summary](https://ppc.land/llms-txt-adoption-rises-8-8x-but-97-of-files-get-zero-ai-requests/), [Rankability tracker](https://www.rankability.com/llms-report/)). Keep the two lines; invest nothing more.
- **MCP Server Cards / AI Catalog** ([SEP-2127, Final, Extensions Track](https://modelcontextprotocol.io/seps/2127-mcp-server-cards)): static card at `<mcp-url>/server-card`, domain catalog at `/.well-known/ai-catalog.json` ([ext repo](https://github.com/modelcontextprotocol/experimental-ext-server-card), [AI Catalog](https://github.com/Agent-Card/ai-catalog)); Python and Go SDK PRs and a Goose client demo exist. Cheap, standards-track, crawlable.
- **schema.org Dataset**: Google says it feeds Dataset Search only, not rich results ([Google docs](https://developers.google.com/search/docs/data-types/dataset)); no evidence found that AI answer engines read it. Generate it, expect nothing.
- **OpenAPI tool loaders**: LangChain's OpenAPI toolkit ([JS docs](https://docs.langchain.com/oss/javascript/integrations/tools/openapi), Python in `langchain_community`), LlamaIndex [`llama-index-tools-openapi`](https://pypi.org/project/llama-index-tools-openapi) (`OpenAPIToolSpec`). The OpenAI Agents SDK has no OpenAPI loader; it connects to MCP via `HostedMCPTool`/Streamable HTTP ([secondary](https://composio.dev/blog/building-mcp-agents-with-openai-agents-sdk)). So: ship `openapi.json` for the first two, the 3-tool MCP server for the third.

**Prior art that changed the plan**

- **Google Data Commons MCP** ([docs](https://docs.datacommons.org/mcp/), [hosted on Google Cloud](https://developers.googleblog.com/en/access-public-data-insights-faster-data-commons-mcp-is-now-hosted-on-google-cloud/), `datacommons-mcp` on PyPI): tools are `search_indicators` → `get_observations` — the two-step catalogue pattern this protocol is designed to avoid. It owns statistics; it does not hold legal thresholds, fees or policy rates. Positioning: complementary, and a possible outreach target (§3).
- **FRED/ALFRED** ([series/observations](https://fred.stlouisfed.org/docs/api/fred/series_observations.html)): `realtime_start/end` vintages are the best prior art for `verifiedDate` + `as_of`; the mandatory `api_key` is why agents do not call it unprompted.
- **Wikidata MCP** ([Wikidata:MCP](https://www.wikidata.org/wiki/Wikidata:MCP)): official, SPARQL-centred; no per-statement verification date against an authority.
- **Web Bot Auth / RFC 9421** ([IETF WG draft](https://datatracker.ietf.org/doc/draft-ietf-webbotauth-httpsig-protocol/)): Ed25519 request signing by Cloudflare, Google, AWS. Confirms the key-at-`.well-known` + Ed25519 toolchain; confirms nobody signs *responses* for agents yet.
- **"Facts for LLMs" projects**: [ARP](https://datatracker.ietf.org/doc/html/draft-deforth-arp-reasoning-protocol-00) (IETF individual draft, self-attested corrections), [gtv](https://pypi.org/project/gtv/) (fact-verifier pilot, Sigstore), Trustlayer `get_signed_fact` (commercial, ES256K + JWKS). None publishes authority-sourced figures under open keys. A parallel review also reports retirement/Monte Carlo MCPs (Cinderfi, Offramp) and insurance-quote MCPs (Sigo, MoneySuperMarket's ChatGPT app) — calculators, not fact publishers; UNVERIFIED here.
- **endoflife.date**: the adoption model — one guessable JSON URL per product, no auth, and agents call it. Data Butler already republishes it; it is also the first outreach target that could plausibly serve `facts.json` itself.

### The top five, in one breath

1. List the 3-tool facts server in every registry (#1). 2. Submit to the Claude Connectors Directory (#2). 3. Make every fact an indexable page and submit the sitemap to Bing (#3). 4. Put the five sister sites at L1 with the static generator (#5). 5. Publish the npm/PyPI client + verifier with framework snippets (#6).

Everything else waits for evidence from webmon: if #3 moves the Bing AI-citation reading, double down on pages; if #1/#2 produce installs (new `agent_mcp_get_fact` events from more than one client fingerprint), do #10.

| Month 2 | #10, #12, #13 | directory status; replies; a second publisher conversation |
| Month 3 (monthly review) | #14 decision; v1.0 wording review per spec §14 | ≥ 3 external publishers at L1, ≥ 1 at L2, or stop investing in the protocol layer and keep the tools |

Kill criterion, stated now so it is not argued later: if by the 2027-01 monthly review `get_fact` has fewer than 50 real (non-probe) calls a week **and** `/f/` pages have no Bing AI citations, the protocol stays as documentation and no further adoption hours are spent; the tools remain because they cost nothing to run.

## 4. What NOT to bother with (and why)

- **RFC 9421 response signing now.** No agent client verifies it; the JWS in the record already travels everywhere the record goes. Revisit when Web Bot Auth verifiers appear in a major client.
- **Sigstore/Rekor, blockchain anchoring, or any "transparency log" infrastructure.** Git history of an immutable changelog in a public repo is the log. Add `prevHash`/`chainHead` (spec §8.1 layer 3) only if someone asks.
- **A Wikidata property proposal** for fact keys. Months of process, no agent discovery gain.
- **An IETF or W3C submission.** Premature with one implementer; the Server Card WG `_meta` note (#13) is the right-sized community action.
- **NLWeb.** Status UNVERIFIED, Microsoft-centric, and its schema.org + RSS inputs are already served (Dataset JSON-LD, `/changes.rss`).
- **More than two llms.txt lines, or llms-full.txt.** 97% of these files are never fetched.
- **Paid directory placements or "AI SEO" services.** No evidence any of them reach an agent's tool list.
- **API keys, rate-limit tiers or auth of any kind** on `/f`. The FRED lesson: an API key is the moment an agent stops calling unprompted. Monetisation, if ever, follows `docs/MONETISATION-DECISION.md` (x402 at the edge), not auth in the protocol.
- **A ChatGPT UI widget before the tool-only app is accepted.** Review rejects relays; a UI does not fix that, usage does.
- **DNS TXT discovery.** Considered and rejected by SEP-2127 for the same reasons it fails here (path-based servers, no HTTP caching).
- **Signing at request time** with the private key on Vercel. Build-time signing is both safer and a stronger claim (spec §8.4).
- **Resolve as a required first call.** The whole design premise is that `get` resolves when it safely can; an agent should never have to learn two tools to get one number.
