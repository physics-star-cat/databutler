# Verified Facts v0.2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Work in a clone of the databutler repo (never a worktree — see the parent `CLAUDE.md`), on a branch off `feat/facts-protocol-v02`, and land by local-path push.

**Goal:** Implement `docs/FACTS_PROTOCOL.md` on Data Butler at conformance level L3: `GET /f/{key}` (+ txt/html/batch/index/resolve), the 3-tool MCP server `/api/mcp/facts`, `get_fact`/`resolve_fact` at the front door, build-time Ed25519 signing with a verifier, `/.well-known/facts.json` + `jwks.json` + Server Cards + `ai-catalog.json`, `openapi.json`, the spec at `/protocol/facts`, the L1 static generator and the public conformance checker — all derived from the area modules so nothing can drift.

**Architecture:** Framework-null Vercel functions, CommonJS, **no npm dependencies** (Node's `crypto` has Ed25519 and JWK import/export; JCS is ~40 lines). Everything new routes through `api/router.js` (Hobby plan: 12 functions; we add zero). Facts are not an area: they are a cross-cutting view, like the hub, built from a new optional `facts` block in each area module. The in-memory fact index is built at cold start from `AREAS`, so it can never disagree with the data files. Signatures are precomputed by `scripts/sign-facts.js` into `data/facts-signatures.json`; the private key never reaches Vercel.

**Tech stack:** Node 22 on Vercel (local v24), `node --test`, built-in `crypto` (`generateKeyPairSync('ed25519')`, `sign(null, …)`, `verify(null, …)`, `createPublicKey({ key: jwk, format: 'jwk' })`), `fetch`.

**Spec:** `docs/FACTS_PROTOCOL.md`. **Adoption plan:** `docs/FACTS_ADOPTION_PLAN.md`.

## Global constraints

- **URLs are forever.** Nothing existing is renamed. New public paths: `/f`, `/f/{key}`, `/f/resolve`, `/facts` (alias → `/f`), `/openapi.json`, `/.well-known/facts.json`, `/.well-known/jwks.json`, `/.well-known/ai-catalog.json`, `/api/mcp/facts`, `/api/mcp/facts/server-card`, `/api/mcp/<server>/server-card`, `/protocol/facts`, `/schema/fact.v0.json`, `/schema/well-known-facts.v0.json`, `/facts/publishers` (later; not in this plan).

New handlers live in `api/_routes/`, new modules in `api/_*.js`; `vercel.json` rewrites point at `api/router.js`. `functions.api/router.js.includeFiles` must add `docs/FACTS_PROTOCOL.md` and `data/facts-signatures.json` (the glob `data/**` already covers the latter).
- **No fabricated data.** Facts are *views* of existing verified figures; this plan adds no figure. Aliases and synonyms are curation, recorded in the modules and reviewed.
- **Tests stay offline.** Live checks go in `verify-hub.sh` via each area's `verify` and a new facts block in `scripts/verify-hub.sh`'s hand-written section.

- **Snapshots** (`tests/snapshot.test.js`): refresh deliberately once per task that changes the public surface (`UPDATE_SNAPSHOTS=1 node --test tests/snapshot.test.js`), read the diff, commit it with the task.
- Run `node --test tests/*.test.js` and `node scripts/sync-areas.js --check` before every commit. Commit after every task; messages end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

### Task 1: JCS canonicalisation, claim hash, detached EdDSA JWS

**Files:** create `api/_jcs.js`, `api/_facts_sign.js`, `tests/jcs.test.js`, `tests/facts-sign.test.js`.

**Interfaces produced:**
- `canonicalize(v) → string` — RFC 8785: object keys sorted by UTF-16 code units, arrays in order, strings via `JSON.stringify`, numbers via `JSON.stringify` (ES `Number::toString`; `-0` → `0`), `null/true/false` literal; throws `TypeError` on `undefined`, functions, symbols, non-finite numbers.
- `CLAIM_FIELDS = ['key','value','unit','period','effectiveFrom','source']`, `ATTESTATION_FIELDS = ['protocol','publisher','key','hash','value','unit','period','effectiveFrom','effectiveTo','source','verifiedDate']`.
- `claimOf(r)`, `hashOf(r) → 'sha256:<64 hex>'`, `attestationOf(r, publisherUrl)`, `attestationHash(att) → hex` (the signatures-file key), `signAttestation(att, privateKeyObject, kid) → '<b64url header>..<b64url sig>'`, `verifyRecord(record, jwks, { now }) → { ok, checks: [{ name, ok, detail }] }` running spec §8.5 steps 1–3 plus `revoked` handling.
- `jwkFromPublicKey(keyObject, kid, validFrom)`, `publicKeyFromJwk(jwk)`.
